# Сквозные проверки BIS

`bis acceptance` проверяет работающий API BIS, а не вызывает агента в обход приложения. Сохраняет сессию диалога, проверяет организацию до отправки поручения, проектный заголовок, ответы, использованные ссылки и скачанные DOCX (включая таблицы и колонтитулы). Старый файл из исходного реестра не может пройти проверку как новый только из-за флага `created`.

Проверка может создавать черновики и расходовать API модели. Запускать на отдельном тестовом экземпляре с подготовленным архивом. Повторных POST-запросов после тайм-аута нет: состояние помечается неизвестным, оставшиеся сценарии не запускаются, результат операции нужно проверить. Отчёт содержит ответы и идентификаторы документов — хранить как данные тестового архива.

## Запуск

```powershell
bis acceptance suite.json --url http://localhost:8081 --report acceptance-report.json
```

Возвращает код 0 только при прохождении всех явно заданных проверок; код 1 — при провале. Структура набора проверяется до сетевых запросов. Ошибки схемы не превращаются в успешный пустой отчёт.

Пример структуры ниже — её нужно привязать к подготовленному архиву и его эталонам. Указанные UUID условные; такой набор не является готовым прогоном на вашей базе.

```json
{
  "name": "Организация Альфа — письма",
  "archive_revision": "alpha-fixture-v1",
  "source_revision": "полный SHA проверяемой версии BIS",
  "contexts": {
    "alpha": {
      "organization_id": "11111111-1111-1111-1111-111111111111",
      "object_id": "22222222-2222-2222-2222-222222222222",
      "token_env": "BIS_ACCEPT_ALPHA_TOKEN"
    }
  },
  "cases": [{
    "id": "letter-and-followup",
    "context": "alpha",
    "failure_layer": "execution",
    "turns": [{
      "message": "Подготовь письмо заказчику о направлении исполнительной документации по нашей форме",
      "expect": {
        "artifact": "new",
        "file_contains": ["Альфа", "исполнительной документации"],
        "file_excludes": ["Бета", "Старая подпись"]
      }
    }, {
      "message": "Где файл письма?",
      "expect": {"artifact": "same", "require_model": false}
    }]
  }]
}
```

`token_env` содержит имя переменной окружения с токеном входа BIS, не API-ключом провайдера. Для A/B нужны отдельные доступные пользователи/токены; организация не переключается подменой поля запроса. При включённом автологине `token_env` можно опустить, но выбранная организация всё равно должна совпасть. Смена A → B → A задаётся порядком сценариев с разными контекстами.

## Проверки

- `text_contains`, `text_excludes`: нормализованное наличие/отсутствие текста. Не являются семантической или юридической оценкой.
- `artifact`: `new` — новый скачиваемый DOCX, отсутствовавший в исходном реестре и предыдущих шагах; `same` — ровно тот же набор файлов, что ранее в сценарии; `none` — нет файлов с признаком созданного результата в ответе.
- `file_contains`, `file_excludes`: проверки содержимого файла. Все обязательные значения должны присутствовать в одном результате, а не быть распределены между несвязанными файлами. Проверяется XML документа, таблиц, колонтитулов; не визуальное расположение элементов или картинки.
- `citation_documents`: UUID документов среди ссылок с признаком `used`. Простое попадание документа в выдачу поиска не считается основанием ответа.
- `forbidden_documents`: UUID, которых не должно быть ни в цитатах, ни в карточках документов.
- `require_model`: по умолчанию true. Известные offline/scripted и детерминированные ответы не засчитываются как работа модели. Для возврата сохранённого файла и специализированного детерминированного конвейера можно явно установить false.

`failure_layer` — исходная категория сценария для разбора провала, не автоматический доказанный диагноз. Для исходных архивов нужны отдельные проверки чтения и заполнение эталонов. Этот инструмент сам не загружает и не размечает архивы и не проверяет их полноту.

В отчёте указаны версии архива и исходников, заданные автором набора, длительность HTTP-запросов чата и пары provider/model из ответа BIS. Эти метаданные не являются независимым доказательством обращения к внешнему провайдеру; для спорного случая нужна трассировка сервера. Общая стоимость API пока не измеряется. Тайм-аут httpx ограничивает отдельные сетевые операции, а не общее время всего набора.

Успех означает только прохождение перечисленных условий (`claim_scope=explicit_acceptance_assertions_only`). `human_review_required=true` сохраняется всегда. Тесты самого проверяющего инструмента используют MockTransport и не доказывают качество реальной модели.
