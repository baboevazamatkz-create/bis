# Изоляция PostgreSQL для тестов BIS

`pytest tests` пересоздаёт схему `public`, применяет Alembic и очищает таблицы после тестов. Тесты API и ORM также меняют данные. Запускайте их в отдельном одноразовом экземпляре PostgreSQL. Рабочая установка и её конфигурация для этого не нужны.

Перед запуском требуются `TEST_DATABASE_URL` и `BIS_TEST_DB_ID`. Адрес должен явно указывать на `127.0.0.1`, выделенный порт, базу `bis_test` и роль `bis_test_runner` с отдельным паролем. Уберите конфликтующий `BIS_DATABASE_URL` и переменные libpq `PG*` из окружения тестового процесса. `TESTING=true` не разрешает доступ. При ошибке конфигурации pytest останавливается. Если соединение невозможно или проверка сервера не пройдена, зависимые тесты завершаются ошибкой до очистки.

## Подготовка одноразового стенда

1. Запустите отдельный PostgreSQL 16 с pgvector на loopback, на свободном порту. При создании экземпляра используйте администратора `bis_test_admin`, новый пароль и пустую БД `bis_test`. При Docker-пробросе порт снаружи должен совпадать с портом PostgreSQL внутри контейнера. Защита сравнивает порт из `TEST_DATABASE_URL` с `inet_server_port()`. В CI изолированный контейнер создаёт GitHub Actions.
2. Получите идентификатор свежесозданного кластера непосредственно из его контейнера командой `docker exec <test-container> psql -XAt -U bis_test_admin -d bis_test -c 'SELECT system_identifier FROM pg_catalog.pg_control_system()'` или через `pg_controldata` на его тестовом каталоге данных. Задайте этот идентификатор в `BIS_TEST_CLUSTER_ID`. Не считывайте его через порт, который предстоит проверять. Сгенерируйте UUIDv4 для `BIS_TEST_DB_ID` и задайте отдельные `BIS_TEST_ADMIN_PASSWORD` и `BIS_TEST_RUNNER_PASSWORD`. Из `backend` выполните `python scripts/provision_test_database.py --port <порт>`. Скрипт сверяет идентификатор до изменения прав и допускает только описанный одноразовый кластер.
3. Уберите обе административные переменные из окружения. Задайте `TEST_DATABASE_URL` с паролем роли `bis_test_runner` (кодируйте спецсимволы для URL), сохраните тот же `BIS_TEST_DB_ID` и выполните `python -m pytest tests`. Без pgvector для локальной проверки можно подготовить базу с `--without-vector` и использовать `BIS_VECTOR_ENABLED=false`. Для проверки векторного поиска используйте стенд с расширением.

## Граница PostgreSQL

Администратор владеет тестовой БД и схемой `bis_test_guard`, а в ней хранится метка UUID. Тестовая роль читает метку и владеет только схемой `public` тестовой базы. Она не является суперпользователем, не состоит в других ролях, не может создавать базы и роли и не имеет CONNECT к другим базам этого экземпляра. Расширение vector, если включено, ставится в отдельную схему, чтобы очистка `public` не удаляла его. На рабочем экземпляре не создавайте эту учётную запись, не копируйте тестовую метку и не открывайте маршрут из CI/TEST к рабочей БД.

Pytest проверяет фактического пользователя и базу, адрес и порт PostgreSQL, UUID и права роли читающим запросом до предоставления соединения SQLAlchemy. Клиент подключается только через loopback. При переносе через порт Docker адрес, который видит PostgreSQL, может отличаться: guard сравнивает его с адресом, записанным администратором при создании метки. Ранее созданный одноразовый экземпляр без этой записи нужно подготовить заново. Проверка охватывает движок приложения и подключение Alembic. Новые тесты должны использовать существующие фикстуры и не открывать собственные соединения через драйвер или подпроцесс в обход SQLAlchemy. PostgreSQL и изоляция сети остаются обязательной второй границей.

Служебные `bis migrate`, `bis local`, Alembic downgrade, демо-скрипты и операция сброса организации не являются запуском pytest. Ограничение тестового процесса к ним применимо только при вызове через его проверенные соединения. Автопоиск установленного BIS в CLI отключён при `BIS_ENV=test`. Явный `BIS_HOME` проверяется без перехода к другим папкам. `deploy/reset-windows.ps1` удаляет каталог данных на уровне файловой системы и никогда не должен быть частью тестов. Для ручного запуска служебных команд используйте явную конфигурацию соответствующего окружения.
