# Аудит рабочего приложения BIS

Проверены текущие шесть разделов ПТО, API, конвейер ИД, чтение источников,
изоляция проектов, сохранение настроек, ошибки сети, голосовой ввод и обновление пилота.

## Исправления этой сборки

| Область | Обнаруженная ошибка | Исправление |
|---|---|---|
| Подготовка ИД | Ответ направлял к скрытому разделу «Сообщить о работе»; результаты заданий отсутствовали в новом интерфейсе | Задания, пробелы, повторная проверка и ZIP комплекта доступны в «Исполнительной документации» |
| Диалоги | Выбранный документ предыдущего диалога оставался в состоянии браузера | Выбор сбрасывается при открытии другой истории; сервер восстанавливает документ именно выбранного диалога |
| История | Поздний ответ мог вернуть старый диалог после нажатия «Новый диалог» | Загрузка истории отменяется при смене диалога или отправке нового сообщения |
| Проекты | История могла показывать диалоги другого объекта при выключенном строгом режиме источников | Явная фильтрация списка и доступа к истории по активному проекту и организации |
| Голос | Микрофон мог продолжать работать после ухода со страницы | Запись и дорожки останавливаются; результат покинутой страницы не отправляется как новое поручение |
| Голос | Наличие Folder ID считалось достаточным для доступности STT | Проверяются и ключ, и каталог, и ffmpeg; отсутствие ключа даёт отдельную ошибку |
| Длинные записи | После 40 частей запись молча обрезалась | Возвращается явная просьба разделить запись; собственное соединение SpeechKit закрывается |
| Загрузки | Некоторые обработчики сначала читали весь файл, затем проверяли размер | Чтение ограничивается до передачи данных парсеру; превышение возвращает HTTP 413 |
| Файлы | Отсутствующий оригинал приводил к HTTP 500 | Возвращается понятная HTTP 404 без раскрытия внутреннего пути |
| Web/API | Неизвестный API-адрес в локальной сборке возвращал HTML оболочки с HTTP 200 | Возвращается JSON HTTP 404; оболочка перепроверяется браузером благодаря no-cache |
| Поручения | Запрет sessionStorage браузером ломал переход к помощнику | Добавлен запасной канал в памяти; поручение привязано к выбранному проекту |
| Реестр | Подписанные документы попадали во вкладку незавершённых | Статусы approved и signed учитываются как готовые |
| Сообщения | Ссылка на документ внутри текста могла завершиться необработанной ошибкой | Ошибка показывается в чате |

Предыдущие исправления сохранности ключа, чтения DOC/RTF, OCR, кнопок и тайм-аутов
включены в сборку; подробности — в AI_CONNECTION_RELIABILITY.md и UI_RELIABILITY.md.

## Проверки

- 377 backend-тестов на отдельной PostgreSQL: API, права и проекты, документы,
  агенты, поиск, конвейер, чтение форматов, настройки и повторный запуск.
- Сборка TypeScript/Vite и Ruff.
- Браузерные сценарии `pilot_workspace.py`, `resilience.py`, `search_and_chat.py`,
  `audit_workflows.py`: реальные контрольные документы и управляемые сетевые ошибки.
- Проверены отмена старой истории, очистка выбора документа, освобождение микрофона,
  список заданий и повторная обработка. Для микрофона использована подмена устройств;
  для проверки состояний очереди — управляемые ответы API. Серверный конвейер отдельно
  покрыт backend-тестами.
- Скрипт обновления проверяется в PowerShell на повторном запуске с сохранением
  файлов, ключей, старой версии и параметров запуска. Установка пакета и запуск
  Windows-приложения в этом сценарии подменены.

## Границы проверки

Проверки выполнены в Linux и Chromium на контрольной базе. Настоящий архив пользователя,
его ключ Яндекса, компьютер Windows, микрофон и установленный AutoCAD/nanoCAD в этой
среде недоступны. Поэтому подтверждена работа проверенных программных сценариев,
а не безошибочность распознавания любых чертежей или доступность внешних сервисов.
Старые скрытые интерфейсы не входят в рабочую навигацию; их серверные функции проверяются
общими тестами. Состав проверок позволяет воспроизводить найденные сбои при следующих изменениях.
