## Ветка разработки и установка

**Состояние:** принято в BIS-003C.

`codex/pilot-readiness` — база новых задач и PR. Установщик Windows-пилота скачивает
закреплённый коммит, обновлятор сначала получает SHA рабочей ветки. Старые Windows-скрипты
загружают архив `8341624`. Linux использует старую ветку через `BIS_BRANCH` по
умолчанию, поэтому она нужна до пересмотра Linux-установки и ранее разосланных ссылок.
[PR №3](https://github.com/baboevazamatkz-create/bis/pull/3) · [Windows](PILOT_WINDOWS.md) ·
[Linux](../deploy/install.sh)

**Ожидает согласования:** смена ветки по умолчанию и настройка защиты. Для
репозитория с одним владельцем предложено требовать PR, зелёные проверки `backend`,
`frontend` и `repository_files` после появления последней в рабочей ветке, запрещать
force-push и удаление ветки. Обязательное независимое одобрение
имеет смысл при наличии второго ревьюера с правом записи.

## Граница тестовой базы

**Состояние:** реализовано в BIS-002.

Тесты используют отдельный PostgreSQL, подтверждают идентичность кластера, тестовой
роли и UUID базы до операций со схемой. Это позволяет воспроизводить проверки
pgvector и Alembic без доступа к рабочим данным. Проверки guard работают
отдельно без PostgreSQL. [PR №1](https://github.com/baboevazamatkz-create/bis/pull/1) ·
[Инструкция](TEST_DATABASE.md)

## Черновик и основания

**Состояние:** реализовано для конвейера ИД.

Ответственность за утверждение принадлежит инженеру. Конвейер хранит ссылки на
основания и состояние проверки, отличает план от факта и требует уточнения при
пробеле или конфликте. Готовность к проверке сама по себе не заменяет утверждение.
[Конвейер ИД](EXECUTIVE_PIPELINE.md) · [Проверка требований](EXECUTIVE_REQUIREMENTS.md)

## Память команды и данные

**Состояние:** рабочий процесс BIS-003 FINAL.

Название ветки, границы задачи, решения и доказательства проверок передаются
через Git и PR. Оригиналы пользовательских документов, рабочая база и секреты
остаются во внешних хранилищах. Для воспроизведения используются синтетические
материалы и изолированные экземпляры. [Правила команды](../AGENTS.md) ·
[Шаблон передачи](templates/HANDOFF.md) · [Изоляция тестов](TEST_DATABASE.md)

В CI и пользовательском Windows ZIP применяется общий [контроль файлов](../deploy/check_repository_files.py).
Архивы исходников, которые GitHub выдаёт по SHA, формируются самим GitHub.
Для таких архивов важен контроль того, что попадёт в рабочую ветку.
