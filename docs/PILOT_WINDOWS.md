# BIS / Синапс — первый запуск текущей версии

Описание шести разделов и управления источниками: [Рабочее место ПТО](PILOT_WORKSPACE.md).

Если BIS-Pilot уже установлен, остановите его через Ctrl+C и обновите backend и интерфейс одной командой:

```powershell
irm https://raw.githubusercontent.com/baboevazamatkz-create/bis/codex/pilot-readiness/deploy/update-pilot-windows.ps1 | iex
```

Обновление сохраняет базу, документы и ключи ИИ, включает ранее запрошенный вход без пароля
и запускает ярлык снова. После запуска обновите браузер через Ctrl+F5.

Быстрая установка в PowerShell, без скачивания вложений из чата:

```powershell
irm https://raw.githubusercontent.com/baboevazamatkz-create/bis/codex/pilot-readiness/deploy/install-pilot.ps1 | iex
```

Скрипт скачивает архив закреплённого коммита из GitHub, проверяет SHA-256 и запускает установку.
Для работы интернет нужен также при загрузке Python и зависимостей.
Ручная установка из того же архива описана ниже.

Для уже установленного пилота можно включить вход без пароля отдельной командой
и затем перезапустить BIS-Pilot:

```powershell
irm https://raw.githubusercontent.com/baboevazamatkz-create/bis/codex/pilot-readiness/deploy/enable-pilot-autologin.ps1 | iex
```

Подключение текстовой модели Яндекса к установленному пилоту:

```powershell
irm https://raw.githubusercontent.com/baboevazamatkz-create/bis/codex/pilot-readiness/deploy/configure-ai-windows.ps1 | iex
```

Помощник запросит Folder ID и скрытый ввод API-ключа, сохранит их локально и проверит
реальный ответ YandexGPT без офлайн-подмены. Нужны активный платёжный аккаунт и доступ
`ai.languageModels.user`. Вопросы разных текстовых агентов идут через общий маршрут `default`.
Зрение, OCR и голос этим помощником не подключаются: их необходимо настраивать и проверять отдельно.
Помощник показывает фактический адрес модели и использует сохранённую пару ключа/каталога,
исключая старые значения этих параметров из окружения. Ярлык пилота также сбрасывает такие
переопределения перед чтением `.env`. Если проверка не проходит, для диагностики нужна полная
строка провайдера с HTTP-кодом, а не только подсказка после стрелки; ключ и `.env` не передавайте.

Этот архив содержит исходный код указанного в RELEASE.json коммита
и заранее собранный интерфейс. Старый установщик install-windows.ps1 скачивает прежнюю ветку.
Это отдельная тестовая установка: существующий BIS и его данные автоматически не переносятся.

## 1. Установка на Windows 10/11 x64

1. Отдельно устанавливать Python не требуется: скрипт найдёт Python 3.12 или скачает
   установщик с python.org, проверит цифровую подпись и установит Python для текущего пользователя.
2. Распакуйте **весь** архив, например в `C:\BIS-package`. Не запускайте скрипт внутри ZIP.
3. Откройте PowerShell в распакованной папке (там, где INSTALL-WINDOWS.ps1) и выполните:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\INSTALL-WINDOWS.ps1
   ```

4. Дождитесь установки зависимостей и подготовки базы. Нужен интернет. Права администратора,
   Docker и Node.js для этого варианта не требуются, если у вас есть право записи в `C:\BIS-Pilot`.
   Если записи нет, задайте доступный **новый** каталог с латинским путём:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\INSTALL-WINDOWS.ps1 -BisRoot C:\Users\Public\BIS-Pilot
   ```

5. Откроется http://localhost:8081. Если браузер открылся раньше сервера, обновите страницу
   после сообщения `BIS работает` в окне запуска.
6. Локальный пилот открывается автоматически под тестовым администратором, без формы входа.
   Его учётная запись: `admin@demo.bis`, пароль `demo12345` (для последующего включения авторизации).
   Это тестовая организация с демонстрационными данными.
   Создайте отдельный реальный объект для проверки собственных документов.

Обычный запуск: ярлык **BIS-Pilot** на рабочем столе либо `C:\BIS-Pilot\START-BIS.cmd`.
Окно запуска должно оставаться открытым. Остановка: Ctrl+C, затем закрыть окно.
Повторный запуск установщика сохраняет настройки и данные пилота. Перед обновлением остановите его.
Существующую папку другой установки скрипт не перезаписывает.
Если изменили BisRoot, во всех следующих путях используйте выбранный каталог.

Архив не содержит ключей ИИ, реальных документов и базы разработчика.
Без подключения моделей доступны интерфейс, текстовое чтение и работа по встроенным правилам;
полноценное понимание сложных чертежей и распознавание сканов требуют настройки ИИ.
Код проверяется в Linux: backend-тесты, сборка интерфейса и браузерные сценарии.
Сам этот новый установочный скрипт ещё не запускался на реальной Windows.

## 2. Папки для ваших документов

Установщик создаёт:

| Путь | Что положить | Уровень в «Библиотеках» |
|---|---|---|
| `C:\BIS-Pilot\library\knowledge\norms` | Нормативы и стандарты | База знаний |
| `C:\BIS-Pilot\library\knowledge\forms` | Чистые формы и шаблоны | База знаний |
| `C:\BIS-Pilot\library\company` | Реквизиты, регламенты и приказы организации | Организация |
| `C:\BIS-Pilot\library\project-01` | Документы одного реального объекта | Проект: выбранный объект |

В заголовке выберите объект, откройте **Базы данных**, выберите базу и подключите папку.
Само копирование файлов ещё не создаёт подключения. В локальном пилоте явно указанный
путь добавляется в разрешённые автоматически. На сервере разрешения задаёт администратор.

Для первого испытания нужен небольшой согласованный комплект по **одному участку работ**:
- рабочие чертежи PDF с титулом, шифром и ревизией; спецификация, лучше исходная XLSX;
- общий журнал работ с настоящими датами;
- сертификаты/паспорта материалов;
- исполнительная схема и протоколы испытаний, если нужны для этих работ;
- ваш пустой бланк АОСР и один правильно заполненный пример;
- описание реально выполненных работ по этому участку.

После синхронизации проверьте ошибки чтения. Для нормативов подтвердите действующие редакции.
Для формы откройте «Настроить заполнение формы», проверьте поля и пробное заполнение,
затем подтвердите карту этой версии. Включите **строгий режим** организации, чтобы пропуски
показывались явно и не заменялись демонстрационными основаниями.

## 3. Подключение ИИ, сканов и голоса

Сначала проверьте, что приложение запускается. Затем настройте провайдера.
Для существующей конфигурации Яндекса можно добавить в `C:\BIS-Pilot\.env`:

```dotenv
BIS_LLM_CONFIG_FILE=C:/BIS-Pilot/config/llm.yandex.json
YANDEX_API_KEY=ваш_ключ
YANDEX_FOLDER_ID=ваш_folder_id
BIS_OCR_PROVIDER=yandex
BIS_STT_PROVIDER=yandex
```

Создайте `C:\BIS-Pilot\config` и скопируйте туда `deploy\config\llm.yandex.json` из этого архива.
Ключ храните локально: присылать его в чат не требуется. В облачном аккаунте нужны доступ
к выбранным языковым моделям, OCR/Vision и SpeechKit STT; их доступность проверяется отдельно.
Настроенный облачный провайдер получает обрабатываемые фрагменты/изображения документов.
Источниками нормативных сведений остаются ваши подключённые папки.

После изменения .env перезапустите BIS. Проверка текстовых провайдеров из PowerShell:

```powershell
& C:\BIS-Pilot\venv\Scripts\bis.exe local --dir C:\BIS-Pilot --setup --then llm-check
```

Эта команда не заменяет проверку OCR, голоса и визуальной модели на реальном документе.
Локальная модель через Ollama возможна отдельно: нужны характеристики ПК (ОЗУ, видеокарта, видеопамять).

### Выбор провайдера в BIS

В разделе **Базы данных → ИИ и качество чтения → Выбрать языковую модель** выберите Anthropic · Claude,
укажите доступную модели (по умолчанию `claude-opus-5-5`) и вставьте API-ключ Anthropic. Ключ хранится
в локальном `.env` и не возвращается интерфейсу; после сохранения нажмите **Проверить ИИ**.
Для других провайдеров в этом же списке доступны OpenAI, Ollama, GigaChat, YandexGPT и совместимый API.

Для обновления существующей установки закройте BIS через Ctrl+C и выполните в PowerShell:

```powershell
irm https://raw.githubusercontent.com/baboevazamatkz-create/bis/codex/pilot-readiness/deploy/update-pilot-windows.ps1 | iex
```

Выбор языковой модели не меняет отдельное подключение OCR: сканы продолжат распознаваться текущим
провайдером OCR. При запросе к Claude BIS отправляет ему нужные фрагменты документов; ключ API
и доступ/оплата Anthropic должны быть настроены в аккаунте Anthropic.

## 4. Первая проверка конвейера и следующий этап

1. В «Базы данных» подключите папки и проверьте «Файлы и ошибки чтения».
   Для ранее загруженного архива используйте «Перечитать документы», для папки — «Обновить базу».
2. В «Проект» найдите документ и нажмите «Задать вопрос». Сверьте ответ с конкретным листом.
3. В «Помощник» сообщите выполненные работы, участок и известные фактические данные.
   Проверьте, нашлись ли проект, записи журнала и сертификаты, затем проверьте черновик в реестре.
4. В «Исполнительные схемы» посмотрите, какие схемы отсутствуют по имеющимся актам,
   и поручите подготовку. Проектные размеры не заменяют исполнительные замеры.
5. Зафиксируйте расхождения: исходный файл/лист, ожидаемое значение, фактический результат.

Следующий этап — калибровка на вашем настоящем архиве: оценить чтение сложных чертежей,
уточнить правила сопоставления и довести один эталонный комплект от сообщения до готового пакета.
Проверка и утверждение инженером остаются отдельным действием.

Если запуск не удался: сохраните текст ошибки из окна. Журналы находятся в
`C:\BIS-Pilot\logs\bis.log` и `C:\BIS-Pilot\data\postgres.log`.
Не удаляйте папку `data` ради повторной установки.

При зависании чата после «Разбираю вопрос» используйте полное обновление выше. В исправленной версии
проект из заголовка запроса передаётся фоновому обработчику; ошибки подготовки сессии приходят в чат;
есть остановка запроса, промежуточные шаги и предельное ожидание (по умолчанию 180 секунд на сервере).
Отмена проверяется между вызовами инструментов и перед фиксацией транзакции. Уже выполняющийся
сетевой вызов прерывается по тайм-ауту своего провайдера; перед повторным созданием проверьте реестр.
Обычный поиск не требует исправной языковой модели и ищет также по имени файла и коротким шифрам РД.
Ошибки API показываются пользователю, а ответы офлайн явно отмечаются. Доступ к облачной модели
проверяется отдельно: обновление не исправляет неверную пару ключа и каталога Яндекса.

## Исправление HTTP-ошибки «No response returned»

Если в стеке есть `bis/main.py`, `slow_log`, `BaseHTTPMiddleware` и `No response returned`,
обновите обработчик журнала запросов. Исправление использует ASGI напрямую, сохраняет потоковую
передачу и не превращает закрытие соединения до начала ответа в эту ошибку. Настоящие ошибки
обработчиков по-прежнему передаются серверу и записываются в журнал.

Остановите BIS через Ctrl+C и выполните полное обновление в начале этой инструкции.
Оно заменяет backend вместе с интерфейсом, сохраняя настройки и данные.
