# BIS / Синапс — первый запуск текущей версии

Быстрая установка в PowerShell, без скачивания вложений из чата:

```powershell
irm https://raw.githubusercontent.com/baboevazamatkz-create/bis/pto-pilot-20261110/deploy/install-pilot.ps1 | iex
```

Скрипт скачивает выпуск из GitHub Releases, проверяет SHA-256 и запускает установку.
Для работы интернет нужен также при загрузке Python и зависимостей.
Ручная установка из того же архива описана ниже.

Этот архив содержит исходный код указанного в RELEASE.json коммита
и заранее собранный интерфейс. Старый установщик install-windows.ps1 скачивает прежнюю ветку.
Это отдельная тестовая установка: существующий BIS и его данные автоматически не переносятся.

## 1. Установка на Windows 10/11 x64

1. Отдельно устанавливать Python не требуется: скрипт найдёт Python 3.12 или скачает
   установщик с python.org, проверит цифровую подпись и установит Python для текущего пользователя.
2. Распакуйте **весь** архив, например в `C:\BIS-package`. Не запускайте скрипт внутри ZIP.
3. Откройте PowerShell в распакованной папке (там, где INSTALL-WINDOWS.ps1) и выполните:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\INSTALL-WINDOWS.ps1
   ```

4. Дождитесь установки зависимостей и подготовки базы. Нужен интернет. Права администратора,
   Docker и Node.js для этого варианта не требуются, если у вас есть право записи в `C:\BIS-Pilot`.
   Если записи нет, задайте доступный **новый** каталог с латинским путём:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\INSTALL-WINDOWS.ps1 -BisRoot C:\Users\Public\BIS-Pilot
   ```

5. Откроется http://localhost:8081. Если браузер открылся раньше сервера, обновите страницу
   после сообщения `BIS работает` в окне запуска.
6. Вход: `admin@demo.bis`, пароль `demo12345`. Это тестовая организация с демонстрационными данными.
   Создайте отдельный реальный объект для проверки собственных документов.

Обычный запуск: ярлык **BIS-Pilot** на рабочем столе либо `C:\BIS-Pilot\START-BIS.cmd`.
Окно запуска должно оставаться открытым. Остановка: Ctrl+C, затем закрыть окно.
Повторный запуск установщика сохраняет настройки и данные пилота. Перед обновлением остановите его.
Существующую папку другой установки скрипт не перезаписывает.
Если изменили BisRoot, во всех следующих путях используйте выбранный каталог.

Архив не содержит ключей ИИ, реальных документов и базы разработчика.
Без подключения моделей доступны интерфейс, текстовое чтение и работа по встроенным правилам;
полноценное понимание сложных чертежей и распознавание сканов требуют настройки ИИ.
Код проверен в Linux: 325 backend-тестов, сборка интерфейса и браузерные сценарии.
Сам этот новый установочный скрипт ещё не запускался на реальной Windows.

## 2. Папки для ваших документов

Установщик создаёт:

| Путь | Что положить | Уровень в «Библиотеках» |
|---|---|---|
| `C:\BIS-Pilot\library\knowledge\norms` | Нормативы и стандарты | База знаний |
| `C:\BIS-Pilot\library\knowledge\forms` | Чистые формы и шаблоны | База знаний |
| `C:\BIS-Pilot\library\company` | Реквизиты, регламенты и приказы организации | Организация |
| `C:\BIS-Pilot\library\project-01` | Документы одного реального объекта | Проект: выбранный объект |

В интерфейсе создайте/выберите объект, откройте **Библиотеки**, подключите эти папки с правильным
уровнем доступа и запустите синхронизацию. Само копирование файлов ещё не создаёт подключения.
Можно использовать свои папки: добавьте разрешённый родительский путь в `BIS_LIBRARY_ROOTS`
в файле `C:\BIS-Pilot\.env`, затем перезапустите программу. Пример JSON: `["D:/MyDocuments"]`.

Для первого испытания нужен небольшой согласованный комплект по **одному участку работ**:
- рабочие чертежи PDF с титулом, шифром и ревизией; спецификация, лучше исходная XLSX;
- общий журнал работ с настоящими датами;
- сертификаты/паспорта материалов;
- исполнительная схема и протоколы испытаний, если нужны для этих работ;
- ваш пустой бланк АОСР и один правильно заполненный пример;
- описание реально выполненных работ по этому участку.

После синхронизации проверьте ошибки чтения. Для нормативов подтвердите действующие редакции.
Для формы откройте «Настроить заполнение формы», проверьте поля и пробное заполнение,
затем подтвердите карту этой версии. Включите **строгий режим** организации, чтобы пропуски
показывались явно и не заменялись демонстрационными основаниями.

## 3. Подключение ИИ, сканов и голоса

Сначала проверьте, что приложение запускается. Затем настройте провайдера.
Для существующей конфигурации Яндекса можно добавить в `C:\BIS-Pilot\.env`:

```dotenv
BIS_LLM_CONFIG_FILE=C:/BIS-Pilot/config/llm.yandex.json
YANDEX_API_KEY=ваш_ключ
YANDEX_FOLDER_ID=ваш_folder_id
BIS_OCR_PROVIDER=yandex
BIS_STT_PROVIDER=yandex
```

Создайте `C:\BIS-Pilot\config` и скопируйте туда `deploy\config\llm.yandex.json` из этого архива.
Ключ храните локально: присылать его в чат не требуется. В облачном аккаунте нужны доступ
к выбранным языковым моделям, OCR/Vision и SpeechKit STT; их доступность проверяется отдельно.
Настроенный облачный провайдер получает обрабатываемые фрагменты/изображения документов.
Источниками нормативных сведений остаются ваши подключённые папки.

После изменения .env перезапустите BIS. Проверка текстовых провайдеров из PowerShell:

```powershell
& C:\BIS-Pilot\venv\Scripts\bis.exe local --dir C:\BIS-Pilot --setup --then llm-check
```

Эта команда не заменяет проверку OCR, голоса и визуальной модели на реальном документе.
Локальная модель через Ollama возможна отдельно: нужны характеристики ПК (ОЗУ, видеокарта, видеопамять).

## 4. Первая проверка конвейера и следующий этап

1. В «Чтение проекта» проверьте извлечённые позиции, привязку к участкам, номера листов,
   марки, единицы, объёмы и непрочитанные фрагменты. Затем — «Факты проекта» и конфликты.
2. В «Сообщить о работе» введите реальное сообщение, например «На участке 123 проложен кабель …».
   Не добавляйте вымышленные даты и марки для прохождения проверки.
3. Проверьте, нашлись ли соответствующие листы, записи журнала и сертификаты;
   сравните черновик АОСР с правильно заполненным образцом и скачайте пакет, если проверки пройдены.
4. Если данных действительно несколько, система должна предложить конкретный выбор.
   При отсутствии доказательств должна показать конкретный пробел, а не придумывать сведения.
5. Зафиксируйте расхождения: исходный файл/лист, ожидаемое значение, фактический результат.
   Это материал для следующей настройки чтения проектов, связей планов и спецификаций,
   распознавания чертежей, дат и проверок готовых документов.

Следующий этап — калибровка на вашем настоящем архиве: оценить чтение сложных чертежей,
уточнить правила сопоставления и довести один эталонный комплект от сообщения до готового пакета.
Проверка и утверждение инженером остаются отдельным действием.

Если запуск не удался: сохраните текст ошибки из окна. Журналы находятся в
`C:\BIS-Pilot\logs\bis.log` и `C:\BIS-Pilot\data\postgres.log`.
Не удаляйте папку `data` ради повторной установки.
