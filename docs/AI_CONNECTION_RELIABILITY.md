# Сохранность подключения ИИ

Исправлены обнаруженные в коде причины нестабильного состояния подключения:

- При отказе облачного провайдера офлайн-ответ раньше сообщал «модель не подключена».
  Теперь он указывает ошибку обращения. Ключ при этом не удаляется. Следующий вызов
  снова рассматривает основной маршрут; офлайн-провайдер не получает постоянный приоритет.
- Сохранение конфигурации и создание шлюза выполняются под общей блокировкой.
  Сборка шлюза со старыми настройками не может заменить новое подключение после сохранения.
- Каждое сохранение создаёт отдельный файл конфигурации без ключа. Сначала записывается
  этот файл, затем атомарно переключается ссылка в `.env`. Уже читаемый файл не обнуляется.
  При ошибке сохранения `.env` прежняя конфигурация остаётся действующей.
- Настройка через интерфейс согласует переменную ключа для текстовой модели, OCR и голоса.
  Старое значение `BIS_YANDEX_API_KEY_ENV` больше не оставляет OCR с другим ключом.
- При запуске `.env` читается с поддержкой кавычек, BOM и `export`. Сохранённые настройки
  локального пилота имеют приоритет над старыми переменными запуска.
- Отсутствие явно указанного файла конфигурации отображается как ошибка настройки,
  вместо молчаливого включения офлайн-режима.
- Устаревший ответ состояния в браузере не отменяет результат нового сохранения.
  Отдельно показаны наличие ключа и результат последнего обращения; при начальной
  загрузке страницы показывается ожидание сведений.

Проверены несколько последовательных сохранений, чтение настроек в новом процессе,
одновременная сборка шлюза и смена настроек, отказ записи файла, временный HTTP 429
с последующим успешным ответом и задержанный ответ статуса в браузере.
Использованы тестовые ключи и управляемые ответы провайдера. Проверка не подтверждает
права, биллинг и срок действия ключа пользовательского аккаунта Yandex Cloud.

После обновления откройте «Базы данных → ИИ и качество чтения». Если ключ уже сохранён,
его можно оставить пустым при повторном сохранении подключения. Затем выполните
«Проверить ИИ» и «Проверить OCR». Ошибки 401/403, ограничения 429 и сетевые отказы
требуют разных действий; конкретное сообщение выводится в приложении.
