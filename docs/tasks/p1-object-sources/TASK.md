# Задание P1 · Проверка источников одного строительного объекта

- **Цель для пользователя** — инженер ПТО загружает комплект в базу выбранного объекта, видит охват чтения каждого файла и по запросу открывает оригинал, подтверждающий найденный фрагмент.
- **Ответственный и роль** — один разработчик BIS ведёт API, интерфейс и регрессионные проверки. Другой агент проводит независимое ревью после появления PR.
- **База (ветка и SHA)** — `codex/pilot-readiness`, `00cdb6404b01136150906085d5ce680fc0707c00`. Ветка реализации `codex/p1-object-sources`. Продолжайте от опубликованного коммита передачи.
- **Контекст** — первая строка продуктовой очереди в [TASKS.md](../../TASKS.md). Загрузка через [libraries.py](../../../backend/bis/api/libraries.py), фоновой импорт через [library_sync.py](../../../backend/bis/services/library_sync.py), извлечение через [archive.py](../../../backend/bis/services/archive.py) и [parsers.py](../../../backend/bis/rag/parsers.py). [reading_report](../../../backend/bis/rag/reading.py) и [hybrid_search](../../../backend/bis/rag/search.py) уже дают данные для интерфейса. [library_access.py](../../../backend/bis/services/library_access.py) включает проектные ORM-фильтры источников по политике `libraries_strict`. [WorkspaceDocuments](../../../frontend/src/modules/executive/WorkspaceDocuments.tsx) в текущей оболочке показывает карточки из [workspace.py](../../../backend/bis/api/workspace.py). [DatabaseHub](../../../frontend/src/modules/executive/DatabaseHub.tsx) показывает подключённые и загруженные через UI проектные файлы.
- **Входит в задачу** — добавить явный поиск фрагментов выбранного объекта в действующем разделе «Проект», рядом с поиском по списку. Использовать существующий RAG и чтение без модели. Оформить результаты как имя файла, цитата с совпадением, физическая страница PDF или имя листа XLSX и действие для доступа к оригиналу. Использовать существующий `openFile` для PDF. Показывать охват чтения даже при пустой выдаче, используя статусы базы проекта. Уточнить в [knowledge.py](../../../backend/bis/api/knowledge.py) и [search_knowledge](../../../backend/bis/agents/builtin_tools.py) семантику явного режима `project` общим правилом отбора источников. Статус частичного чтения выводить из сохранённого отчёта, включая `complete=false` без пустых страниц и предупреждений. Для старых записей без отчёта показать, что охват неизвестен. Для полностью непрочитанного файла использовать запись и ошибку импорта даже при отсутствии карточки документа.
- **За пределами задачи** — следующий сценарий АОСР, качество OCR на рабочих архивах, новые провайдеры, извлечение фактов из чертежей, изменение ролей, общий рефакторинг RAG или агентов, новая схема БД.
- **Проверки, окружение и тестовые данные** — [учебный комплект и протокол](#учебный-комплект-и-протокол), backend-тест с реальной загрузкой и проверками ниже, сборка frontend и ручной прогон действующего интерфейса.
- **Блокировки и необходимые разрешения** — использовать [одноразовый PostgreSQL](../../TEST_DATABASE.md), временное файловое хранилище, отдельный тестовый сервер для браузера и локальные настройки без ключей, OCR и LLM. Действуют ограничения [AGENTS.md](../../../AGENTS.md), включая рабочую установку, рабочую БД, миграцию 0009, merge и деплой.
- **Результат** — PR из `codex/p1-object-sources` в `codex/pilot-readiness` с тестом, фактическими результатами проверок и кратким отчётом по [HANDOFF](../../templates/HANDOFF.md). Приложить ожидаемые и фактические ссылки на оригиналы, HTTP-статусы и снимки или запись ручной проверки экрана.

## Критерии приёмки

1. **Импорт и охват.** В «Базах данных → База проекта» после загрузки комплекта A видны четыре файла. РД показывает 2/2 страницы с текстом, спецификация 2/2 листа с текстом, `Quality.pdf` показывает частичное чтение 1/2 и страницу 2 без текста, `Scan-only.pdf` показывает ошибку чтения с причиной. Результат одинаков после обновления страницы. Частично прочитанный файл с непустой, но слишком короткой страницей и отчётом `complete=false` остаётся частичным даже без отдельного предупреждения. Статус описывает охват извлечения текста.
2. **Доказательство по запросу.** В поиске фрагментов раздела «Проект» на A первый результат `KLAB471` содержит `120 m`, `SHEET 7` и физическую страницу 2 файла `RD-TRAIN-17.pdf`. Оригинал открывается на странице 2. Для `SPECLAB082` первый результат показывает `Specification.xlsx`, лист «Кабели», строку позиции 2 с 120 м. Действие отдаёт исходный XLSX; номер физической страницы отсутствует. Для `QUALITYLAB309` первый результат показывает `Quality.pdf`, страницу 1, текст о партии и пометку о неполном чтении. Байты открываемых оригиналов совпадают с загруженными по SHA-256.
3. **Нет подтверждения.** Запросы `SCANNEDLAB701` и `UNREADLAB884` при выключенном OCR возвращают пустой список подтверждённых фрагментов. Экран сообщает, что совпадений в извлечённом тексте нет, и показывает неполноту по объекту или даёт видимый переход к списку проблемных файлов. Ни пустой поиск, ни статус «в индексе» не означают, что документ проверен инженером. При недоступных эмбеддингах те же три положительных запроса проходят лексическим путём.
4. **Граница объекта.** API поиска и инструмент RAG в явном режиме `project` при A возвращают только допустимые активные источники A, даже с отключённой `libraries_strict`. Под B тот же запрос `KLAB471` первым возвращает `375 m` и страницу 2. `DRAWINGOBJECTB` под A и `DRAWINGOBJECTA` под B дают пустую выдачу в лексическом прогоне. Исключены источники организации без привязки к объекту и общая база. Без выбора объекта UI предлагает его выбрать, API возвращает 409 и инструмент сообщает, что нужен объект. Объект другой организации даёт 400 по имеющемуся контракту. После переключения A → B в UI очищаются выдача и охват A, включая случай незавершённого запроса.
5. **Оригинал и версии.** Маршрут открытия оригинала из проектного результата возвращает 404 для версии или документа B при активном A и для источника другой организации. Проверить в обоих режимах политики именно маршрут этого сценария. Активный оригинал A доступен через те же действия пользователю с правом чтения. Отключённое подключение и заменённая версия исчезают из проектной выдачи, в том числе после обновления UI. Существующие режимы поиска по организации и общей базе сохраняют свои контракты.

## Учебный комплект и протокол

Из корня репозитория в Python-окружении backend:

```sh
bis_p1_dir="$(mktemp -d)"
python docs/tasks/p1-object-sources/make_corpus.py "$bis_p1_dir/corpus"
```

| Объект | Файл | Эталон |
| --- | --- | --- |
| A | `RD-TRAIN-17.pdf` | `KLAB471` → стр. 2, лист 7, 120 м, `DRAWINGOBJECTA` |
| A | `Specification.xlsx` | `SPECLAB082` → «Кабели», позиция 2, 120 м |
| A | `Quality.pdf` | `QUALITYLAB309` → стр. 1. `SCANNEDLAB701` находится только в изображении на стр. 2 |
| A | `Scan-only.pdf` | `UNREADLAB884` находится только в изображении на стр. 1 |
| B | `RD-TRAIN-17.pdf` | То же имя, шифр, лист и `KLAB471` → стр. 2, 375 м, `DRAWINGOBJECTB` |

- В одной тестовой организации создать два объекта A и B. В режиме без OCR загрузить содержимое соответствующей папки через «Базы данных → База проекта → Загрузить файлы». Для API-теста использовать `POST /api/libraries/upload` и существующие фикстуры, проверить состояние файлов после синхронизации. Открывать рабочие экранные маршруты с настоящим backend, без `VITE_DEMO=1`.
- Из `backend` на стенде выполнить `python -m pytest tests` и `ruff check bis tests guard_tests scripts/provision_test_database.py`. Если регрессионный тест в PR добавлен отдельным модулем, привести команду запуска модуля в описании PR. Из `frontend` выполнить `npm ci` и `npm run build`. Для теста без эмбеддингов явно отключить векторный путь или подставить недоступный провайдер в тесте.
- Независимый ревьюер сверяет diff PR с базой и повторно генерирует корпус. Сверяет все пять сценариев, в том числе смену объекта, 404 по маршруту оригинала B при контексте A, доступ пользователя чтения, точные страницы и SHA-256. Отдельно прослеживает в коде, что отбор объекта и актуальной версии выполняется до ранжирования и применяется в лексическом и векторном путях, и что существующие записи без отчёта читаются без ложного статуса полноты. Сверяет CI с SHA головы PR и оставляет воспроизводимые замечания или вывод об отсутствии блокирующих замечаний.
