PR реализации готовит разработчик.
- **Выполнено и ключевые решения** — существующие загрузка, индекс и экран проекта дают основу. Добавьте в действующую оболочку явный режим поиска фрагментов без LLM. Установите точную границу для явной области `project` независимо от `libraries_strict`, сохранив другие области поиска. На экране базы проекта отразите охват текста и различайте частичный импорт и ошибку файла. Для PDF различайте физическую страницу и обозначение листа в тексте. Оригинал XLSX скачивается с указанием имени листа в результате.
- **Проверки** — на базовом SHA завершились успешно `python -m pytest -q tests/test_database_boundary.py tests/test_libraries.py tests/test_search_resilience.py tests/test_pilot_workspace.py tests/test_reading_integrity.py tests/test_project_reading.py` в контейнере PostgreSQL 16 с pgvector, созданном для этого прогона и проверенном guard. Генератор создал пять файлов. В прогоне через архивный парсер и `GenericChunker` без OCR РД A и B дали 2/2 страницы с целевым фрагментом на странице 2, спецификация 2/2 листа, паспорт 1/2, документ-скан 0/1.
- **Воспроизведение на базовом API** — на втором одноразовом PostgreSQL загрузили пять файлов через `POST /api/libraries/upload` без OCR и векторного поиска. В A API файлов вернул `partial` для паспорта и `error` для скана. `GET /api/workspace/documents?category=project&q=KLAB471` вернул карточку A без текста совпадения и страницы. `GET /api/knowledge/search?scope=project&q=KLAB471` под A вернул фрагмент B при выключенной `libraries_strict`. После включения политики в той же тестовой организации найден фрагмент A на странице 2, фрагмент B исключён. Запросы использовали JWT и заголовок `X-BIS-Project`. Это описывает наблюдение на базе, до реализации P1.

Сгенерировать комплект, загрузить в A и B через существующий API и воспроизвести выдачу до правок. Далее реализовать критерии, приложить наблюдения и передать PR независимому ревьюеру. Ревьюеру нужны задание, базовый SHA, SHA головы PR и ссылка на PR.
- **Риски, блокировки и разрешения** — со старого интерфейса `#/id/knowledge` маршрутизирует в «Базы данных», поэтому правка прежней страницы `Knowledge.tsx` сама по себе не меняет пользовательский путь. Поиск по карточкам `/workspace/documents` возвращает документы без найденного текста и страницы. `/libraries/{id}/files` сейчас сводит частичность к пустым страницам или предупреждениям, хотя отчёт имеет и другие признаки. Доступ к старым маршрутам оригиналов зависит от политики. Проверяйте границу через маршрут, используемый новым интерфейсом. Применяйте ограничения [AGENTS.md](../../../AGENTS.md) и [TEST_DATABASE.md](../../TEST_DATABASE.md). Merge и деплой требуют отдельного разрешения.
