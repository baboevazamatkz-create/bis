PR реализации готовит разработчик.

Установите точную границу для явной области `project` независимо от `libraries_strict`, сохранив другие области поиска. На экране базы проекта отразите охват текста и различайте частичный импорт и ошибку файла. Для PDF различайте физическую страницу и обозначение листа в тексте. Генератор создал пять файлов. В прогоне через архивный парсер и `GenericChunker` без OCR РД A и B дали 2/2 страницы с целевым фрагментом на странице 2, спецификация 2/2 листа, паспорт 1/2, документ-скан 0/1.

В A API файлов вернул `partial` для паспорта и `error` для скана. `GET /api/workspace/documents?category=project&q=KLAB471` вернул карточку A без текста совпадения и страницы. `GET /api/knowledge/search?scope=project&q=KLAB471` под A вернул фрагмент B при выключенной `libraries_strict`. После включения политики в той же тестовой организации найден фрагмент A на странице 2, фрагмент B исключён. Запросы использовали JWT и заголовок `X-BIS-Project`. Это описывает наблюдение на базе, до реализации P1.
- **Пропущенные проверки и причины** — браузерная приёмка, полный backend-набор и сборка frontend относятся к PR реализации. В этой ветке добавлены задание и учебный набор.

Сгенерировать комплект, загрузить в A и B через существующий API и воспроизвести выдачу до правок. Далее реализовать критерии, приложить наблюдения и передать PR независимому ревьюеру. Ревьюеру нужны задание, базовый SHA, SHA головы PR и ссылка на PR.
- **Риски, блокировки и разрешения** — со старого интерфейса `#/id/knowledge` маршрутизирует в «Базы данных», поэтому правка прежней страницы `Knowledge.tsx` сама по себе не меняет пользовательский путь. Поиск по карточкам `/workspace/documents` возвращает документы без найденного текста и страницы. `/libraries/{id}/files` сейчас сводит частичность к пустым страницам или предупреждениям, хотя отчёт имеет и другие признаки. Доступ к старым маршрутам оригиналов зависит от политики. Проверяйте границу через маршрут, используемый новым интерфейсом. Применяйте ограничения [AGENTS.md](../../../AGENTS.md) и [TEST_DATABASE.md](../../TEST_DATABASE.md). Merge и деплой требуют отдельного разрешения.

## Результат реализации P1

- **Задача и цель** — [TASK.md](TASK.md). Инженер ПТО видит охват чтения в базе объекта, находит текстовый фрагмент в разделе «Проект» и открывает действующий оригинал.
- **Ветка и база** — `codex/p1-object-sources` → `codex/pilot-readiness` (`00cdb6404b01136150906085d5ce680fc0707c00`). Реализация начата с `065ee5cbe19a5a4074db73010fca46d5a65a982a`. Код проверен на `2abc69f04b64a170dbcbd7f4508a2a168aeade6b`. Вершина с приложенными результатами указана в PR.
- **Решения** — API и инструмент RAG применяют один предикат активных источников проекта до ранжирования. Проектная ссылка на оригинал повторно применяет тот же предикат. Интерфейс использует `scope=project&fragments=true`, то есть поиск по извлечённому тексту без инициализации эмбеддингов или реранкера. XLSX открывается скачиванием, имя листа видно в результате. Для старых XLSX индекс восстанавливает имя из сохранённого заголовка листа.
- **Стенд** — отдельные PostgreSQL 16 с pgvector и проверкой `bis_test_guard` для pytest и браузера, временное хранилище, ASGI и собранный Vite на loopback. OCR и внешние модели отключены. Chromium управлялся через Playwright. Файлы A и B выбраны через штатную кнопку загрузки. Фактические ссылки, статусы и SHA‑256 сохранены в [протоколе браузера](evidence/browser-results.json).
- **Снимки интерфейса** — [четыре файла после обновления](evidence/01-coverage.png), [РД и физическая страница PDF](evidence/02-pdf-fragment.png), [позиция XLSX на листе «Кабели»](evidence/03-xlsx-fragment.png), [паспорт с неполным чтением](evidence/04-partial-fragment.png), [пустая выдача с видимым охватом](evidence/05-no-fragment.png).

### Поправки после независимого ревью PR №8

- Поиск одной марки или шифра в режиме фрагментов требует совпадения обозначения целиком. `KLAB120`, `SCANNEDLAB120` и `RD-TRAIN-99` дали пустую выдачу в Chromium. `KLAB471` по-прежнему открывает РД на физической странице 2.
- Для старого PDF с сохранённым общим MIME проектный маршрут определяет тип по имени файла. Регрессия проверяет штатную загрузку, физическую страницу, `Content-Type: application/pdf` и байты оригинала.
- Целевой прогон `tests/test_p1_object_sources.py tests/test_search_cache.py tests/test_search_resilience.py tests/test_database_boundary.py` — 12 прошли. Собранный интерфейс повторно проверен на новом одноразовом PostgreSQL. Снимки и протокол обновлены.
