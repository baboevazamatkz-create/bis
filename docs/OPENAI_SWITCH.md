# Переключение на OpenAI

Исправлены обнаруженные ошибки настроек:

- Выбор провайдера очищал уже введённый ключ. Теперь ввод сохраняется до подтверждённой записи.
- Ключи OpenAI с префиксом `sk-proj-`/`sk-svcacct-` распознаются формой. Сервер отклоняет их,
  если явно выбран другой провайдер; старая форма подключения направляет такие ключи в настройку OpenAI.
- При выборе OpenAI сохранялся Claude в маршруте зрения и в проверках. Теперь OpenAI используется
  для текста, инструментов, изображений и OCR, без обращений к прежнему Claude.
- Раньше интерфейс выставлял успешный статус самостоятельно. Теперь он получает конфигурацию
  из ответа сервера, сравнивает провайдера и только затем очищает ключ и закрывает форму.
- Загрузка статуса ИИ больше не ждёт список библиотек; эти запросы запускаются независимо.

Обновление Windows поддерживает `-ConnectOpenAI`: после установки свежего кода оно запрашивает
ключ скрытым вводом и запускает `deploy/set-openai.py`. Этот шаг записывает и проверяет локальную
конфигурацию через stdin, без HTTP-сервера BIS, БД и запросов к облачной модели. Ключ не передаётся
в аргументах процесса. После записи BIS запускается с OpenAI и моделью `gpt-4.1-mini`.

Проверка сохранения не подтверждает сетевую доступность OpenAI или баланс API аккаунта.
Голосовая транскрибация имеет отдельное подключение STT.

Проверено: 391 серверный тест; сборка интерфейса; Ruff; браузерный переход Anthropic → OpenAI,
сохранность введённого ключа при смене выбора и восстановление подтверждённого OpenAI после reload.
Отдельный процесс конфигурации проверен на синтетическом ключе без работающего HTTP-сервера BIS.
Реальный ключ пользователя не использовался, реальный Windows здесь не запускался.
