# BIS: отдельные рабочие пространства

09.11.2026. Текущий приоритет — **автоматизация исполнительной документации для инженера ПТО**.
Списание материалов, учёт, закрытие работ и договорная работа пока не входят в этот блок.
Интеллект проекта теперь называется **«Синапс»**. Технические адреса `/brain` и существующие данные сохранены.

## Первый блок: исполнительная документация

По умолчанию приложение открывает рабочее пространство ИД. Прямая ссылка: `/#/id/overview`.

В интерфейсе остаются:

- Рабочий стол: документы ИД, черновики, замечания, последние акты, переходы к подготовке и проверке.
- Помощник ПТО: поиск оснований, подготовка АОСР/АООК и схем, вопросы по документам и нормативам.
- Комплектность ИД: проверка ссылок из актов на документы качества, протоколы, схемы и РД.
- Реестр ИД: АОСР, АООК, схемы, реестры ИД и журналы; выгрузка реестра по объекту в Excel.
- Подготовка акта: выбор АОСР или АООК, участники из объекта и назначений, проверка и создание черновика.
- Исходные документы: РД, сертификаты, паспорта качества, протоколы, приказы, съёмки и фото.
- Синапс: поиск документов, карточки, связи, состояние чтения и досчёт архива.
- Объекты, организации, представители, назначения и нормативная база как основания для ИД.
- Настройки блока: реквизиты организации и шаблоны АОСР.

Материалы, перечисленные в акте, и документы об их качестве остаются частью ИД.
Операции прихода, расхода, списания, М-29 и КС-2/КС-3 скрыты из рабочего пространства.
Загрузка архива из этого блока не включает автоматический договорный анализ.

## Отдельный интерфейс остальных направлений

Существующие направления сохранены в `/#/platform/feed`. Переходы к ним не показываются в меню ПТО.
Договоры: `/#/platform/contracts`; учёт и закрытие: `/#/platform/works`.
Их интерфейс загружается отдельно, по обращению к соответствующему адресу.
Это временное общее пространство остальных направлений: собственные интерфейсы для них выделяются позже.

Исходные данные и файлы не удалялись, базы для блоков не копировались.
Идентификаторы объектов, организаций, документов и связей, авторизация, хранилище и индекс остаются общими.
Так дальнейшее соединение блоков не потребует повторной загрузки архивов.

## Границы на сервере

- Чат принимает `workspace: "executive" | "platform"`; по умолчанию старые клиенты работают с платформой.
- В блоке ИД доступны ПТО, CAD, нормоконтроль и помощник. Делегирование другим специалистам отклоняется.
- Набор действий ограничен созданием АОСР, АООК и исполнительных схем; доступны относящиеся к ИД инструменты чтения.
- Истории диалогов разделены по рабочему пространству. Диалог другого блока нельзя случайно продолжить.
- Реестр документов фильтруется **до пагинации**: `GET /api/documents?workspace=executive`.
- Исходные документы: тот же адрес с `collection=sources`; поиск Синапса принимает `workspace=executive`.
- Общие права пользователя сохраняются. Выгрузка журнала через инструмент требует `documents:write`.

Это разделение интерфейсов и сценариев. Оно не создаёт новые организации или отдельные роли доступа;
существующие общие API и настроенные фоновые задачи не отключаются глобально.

## Код

- `frontend/src/modules/executive/`: рабочее пространство ПТО, рабочий стол, его настройки и подсказки.
- `frontend/src/modules/platform/`: отдельный интерфейс остальных направлений.
- `frontend/src/modules/navigation.ts`: допустимые маршруты и меню каждого пространства.
- `backend/bis/modules/executive.py`: документы, специалисты, инструменты и инструкции блока.
- Общие страницы форм и сервисы используются повторно; логика расчётов и чтения не дублируется.

## Проверка

При выделении блока прошли 198 тестов backend. После реализации конвейера полный набор — 226 тестов, все успешны.
Сборка интерфейса и линтер успешны.
В Chromium с тестовыми ответами API проверены меню, разделение реестров, создание АООК, комплектность,
параметры чата, загрузка, настройки, Синапс, отдельный интерфейс платформы и экран шириной 390 px.
Проверки backend выполнялись с PostgreSQL; браузерные снимки показывают тестовые данные.
