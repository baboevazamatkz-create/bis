# Проверка отзывчивости рабочего места ПТО

Причина общей блокировки на странице баз: один флаг busy охватывал и команду,
и последующую загрузку всех списков. Запросы без предельного времени ожидания
могли оставлять этот флаг включённым. Интервальный опрос создавал новые запросы,
даже когда предыдущие ещё выполнялись.

Исправления:

- Сохранение настроек, проверка модели, OCR и изменение базы имеют отдельные блокировки.
  Повторное нажатие во время выполнения той же операции не отправляет дубликат.
- Успешная команда освобождает управление до обновления сведений. Частичная ошибка
  чтения списков сохраняет уже полученные данные и показывает сообщение.
- Опрос запускается после завершения предыдущего прохода; загружаются файлы текущей
  вкладки. Переход между вкладками отменяет ненужное чтение.
- Запросы ограничены по времени до окончания чтения ответа: обычные — 30 секунд,
  файлы — 90, распознавание речи — 120, проверки ИИ/OCR — 130, загрузка — 600.
  Истечение ожидания не означает отмену уже начатой серверной операции; автоматического
  повторения команд изменения данных нет.
- Сообщения остаются видимыми при прокрутке. Долгие проверки имеют подпись состояния.
  Результат проверки старых настроек не выдаётся за проверку нового подключения.
- Открытие Word/Excel использует один запрос и сохраняет исходное имя файла.
- Ошибка получения проектов имеет кнопку повтора. Удалённый ранее выбранный объект
  сбрасывается. Ошибки открытия истории чата отображаются пользователю.

Проверки в Chromium на отдельной базе с контрольными файлами:

- `frontend/e2e/pilot_workspace.py`: шесть разделов, папка, поиск, договор, перечитывание,
  очистка с сохранением оригиналов, настройки и мобильная ширина.
- `frontend/e2e/search_and_chat.py`: ошибки поиска, прерванный ответ, остановка чата.
- `frontend/e2e/resilience.py`: задержанные ответы, независимость кнопок, один проход
  опроса, сетевые ошибки, тайм-аут получения заголовков/тела/файла, одно скачивание
  с правильным именем, списки документов всех четырёх типов.

Сетевые отказы в последнем сценарии воспроизводятся управляемой подменой ответов.
Эти проверки не подтверждают доступность пользовательского аккаунта Yandex Cloud
или качество чтения пользовательского архива. Проверка OCR и модели с реальными
настройками выполняется кнопками в локальном приложении.
