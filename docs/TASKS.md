# Текущие задачи BIS

Таблица задаёт рекомендуемую последовательность. Координатор выдаёт конкретную
задачу с целевым результатом, веткой и границами работы по [шаблону](templates/TASK.md).
Состояние выполнения сверяется по ссылке на PR и проверкам.

## Первые продуктовые задачи

| Задача | Результат для инженера ПТО | Приёмка |
|---|---|---|
| P1 · Проверка источников одного объекта | Инженер подключает учебный комплект РД, спецификацию и документ качества и видит, какие файлы пригодны для работы. | На воспроизводимом наборе поиск возвращает нужный лист или страницу, неполное чтение видно в интерфейсе, одноимённый источник соседнего объекта исключён. Зафиксированы ожидаемые ссылки и ошибки. |
| P1 · От сообщения о работе к черновику АОСР | Для одного вида работ система собирает черновик, который можно проверить и скачать с комплектом оснований. | На эталонном сценарии сверены объект, место, даты, редакция РД, фактическая партия и перечень файлов в DOCX/ZIP. Если обязательного основания нет, отображается конкретный пробел. Повтор с тем же `request_id` сохраняет один результат. Использовать комплект из предыдущей задачи. |
| P2 · Проверка и исправление комплекта | Инженер понимает причину блокировки и продолжает работу с тем же черновиком после уточнения. | В одном сквозном сценарии неподтверждённое основание блокирует готовность, его замена требует повторной проверки, результат виден после перезагрузки, пользователь с правами просмотра не может утвердить. |

Фиксируйте исходную ревизию, эталон, тестовый контур и результаты сравнения.
Прогоны через [bis acceptance](ACCEPTANCE.md) создают черновики и выполняются на
отдельном согласованном стенде.

## Блокировки и backlog

| Приоритет | Что требуется |
|---|---|
| P0 перед сетевым пилотом | Принять браузерный вход Docker на отдельном стенде. Проверить вход с действительной учётной записью и отказ без аутентификации. Защита локального входа уже объединена в [PR №4](https://github.com/baboevazamatkz-create/bis/pull/4). Продуктовые задачи можно вести на изолированном стенде. |
| P1 при выборе рабочей ветки по умолчанию | Получить разрешение владельца. Подготовить обязательный PR и CI-проверки, сохранить старую ветку, перепроверить новую облачную задачу и ссылки установки. [Решение о ветках](DECISIONS.md#ветка-разработки-и-установка) |
| P2 после проверки Docker | Решить, как переводить Linux-установщик с прежней ветки. Проверить чистую установку, обновление существующего клона и вход в браузере. |
| P2 после продуктового прогона | Свести повторяющиеся правила извлечения и подготовки файла акта только после появления тестов, которые фиксируют действующие контракты, факты и связи. |

Локальная миграция `0009`, изменение процесса выпуска Windows и возврат отдельного
интерфейса платформы требуют отдельных задач и оценки объёма. Новые наблюдения
добавляются в backlog с воспроизведением и влиянием на пользователя.
