# AI-команда BIS

Командные роли относятся к разработке репозитория. Начальный контекст для всех ролей находится в [AGENTS.md](../AGENTS.md). Актуальное состояние и приоритеты ведутся в [CURRENT_STATE.md](CURRENT_STATE.md) и [TASKS.md](TASKS.md). Решения с причинами и последствиями фиксируются в [DECISIONS.md](DECISIONS.md).

Три постоянные роли — координатор, разработчик и независимый ревьюер. Архитектурную оценку назначают по необходимости.

| Роль | Ответственность | Что передать дальше |
|---|---|---|
| Координатор | Сверяет цель пользователя с состоянием репозитория, выбирает задачу, назначает ответственных и устраняет пересечение работ. | Принятая задача с критериями приёмки и блокировками. |
| Архитектор | Уточняет границы системы, API, данные, совместимость и влияние на права доступа. Проверяет риски и предлагает решение для задачи. | Решение со ссылками на код и список сценариев, которые нужно проверить. |
| Разработчик | Реализует согласованную задачу в отдельной ветке, запускает проверки и готовит PR. | Ветка, SHA, PR и отчёт по проверкам. |
| Ревьюер | Независимо сверяет diff с задачей, проверяет риски, тесты и затронутые контракты. | Замечания с путём и способом воспроизведения либо вывод об отсутствии блокирующих замечаний. |

Один агент может последовательно выполнять несколько ролей. Для независимого ревью передайте другому агенту задачу, базовый SHA и ссылку на PR. При смене агента используйте [шаблон передачи](templates/HANDOFF.md). Новый агент сверяет указанные ссылки с Git и использует общие документы. Координатор сообщает пользователю решения, требующие его согласия.

## Первый чат «BIS | Координатор»

Откройте новый чат в проекте `baboevazamatkz-create/bis` и явно выберите `codex/pilot-readiness` после публикации этой документации в рабочей ветке. Задайте имя «BIS | Координатор» и отправьте:

> Ты координатор проекта BIS. Прочитай `AGENTS.md`, `docs/PROJECT_CONTEXT.md`, `docs/CURRENT_STATE.md` и `docs/TASKS.md` на актуальной вершине `codex/pilot-readiness`. Сверь открытые PR и блокировки. Выбери первый доступный продуктовый сценарий, подготовь задание по `docs/templates/TASK.md` с измеримыми критериями приёмки и ссылками на код. Действуй в рамках полномочий из `AGENTS.md`.

До публикации можно проверить онбординг на ветке PR с этой документацией.
