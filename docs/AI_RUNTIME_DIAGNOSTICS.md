# Если ИИ перестаёт отвечать через несколько минут

Для диагностики на работающем Windows-пилоте:

```powershell
irm https://raw.githubusercontent.com/baboevazamatkz-create/bis/codex/pilot-readiness/deploy/diagnose-ai-windows.ps1 | iex
```

Скрипт наблюдает приложение около шести минут. Во время наблюдения используйте BIS,
чтобы повторился сбой. Приложение останавливать не нужно. При сетевых тайм-аутах
наблюдение может занять больше времени.

Отчёт `AI-DIAGNOSTICS-*.txt` сохраняется в корне установленного пилота. Он содержит
версию сборки (если доступна), наличие сохранённого ключа, факт изменения файлов
настроек без их значений, статус API, длительность ответа и ошибки модели.
Раз в три минуты выполняется штатная проверка моделей: это реальные короткие
обращения к настроенным провайдерам. Документы для этой проверки не передаются.

Настройки не изменяются, приложение не перезапускается. Значения секретных
переменных из `.env` и строки Authorization маскируются. Полный `.env` и ключ
передавать не нужно. Для разбора достаточно текста диагностического отчёта.

Цель — отличить потерю конфигурации, отказ аутентификации, ограничения провайдера,
сетевой тайм-аут и недоступность самого API. Наличие фоновых заданий само по себе
не доказывает, что они вызвали отказ: для этого сопоставляются время и ответы сервиса.
